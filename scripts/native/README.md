# Native Vercel build

The workstation's OpenCV 5 libraries need glibc 2.43; Vercel's runtime supplies
far less, so anything linked here is unusable there. `Dockerfile` pins a Debian
11 userland (glibc 2.31) and builds OpenCV 4.12 against it. It is a **build
image**, not a deployed service. All application work runs in Vercel functions.

## Usage

```bash
just deploy           # production
just deploy-preview   # unaliased preview
```

`server/scripts/deploy-prebuilt.sh` generates the frontend on the host, runs
`build.sh` to compile the bundles in the image, checks every bundle in the plan
reached the output, then uploads with `vercel deploy --prebuilt`.

To build without deploying, run `scripts/native/build.sh`; it writes
`server/.vercel/output`.

## How the image is managed

`build.sh` tags the image with a hash of `Dockerfile` and builds it only when
that tag is absent. Editing the Dockerfile rebuilds once; every later build
reuses the result. There is nothing to invalidate by hand.

The first build compiles OpenCV from source and takes roughly 10-20 minutes.
Cargo's registry, target directory and scratch state live in the
`daily-mirror-build` Docker volume, which is what keeps a warm build near 20
seconds. Removing that volume costs a slow rebuild, nothing more.

A cargo cache from an earlier build tree can be copied in to skip that first
slow build, adjusting the source path. Fingerprints are keyed to the
toolchain's path, so a cache from a differently laid out image rebuilds
anyway; correctness does not depend on it.

```bash
docker volume create daily-mirror-build
docker run --rm -v daily-mirror-build:/dst -v /path/to/old/container-target:/src:ro \
  debian:bullseye-slim sh -c 'mkdir -p /dst/target && cp -a /src/. /dst/target/'
docker run --rm -v daily-mirror-build:/build debian:bullseye-slim \
  chown -R "$(id -u)":"$(id -g)" /build
```

The second command matters: files copied as root are unwritable by the build,
which runs as the calling user.

The image carries its own Rust 1.96.0, `cargo-nextrs` (pinned to the rev in
`server/Cargo.toml`), `cargo-zigbuild` and `zig`. `nextrs` must be compiled
inside the image: a host-built CLI needs glibc 2.43 and cannot run there.

## Private assets

`server/resources/vision` is intentionally gitignored and **cannot be
regenerated by anything in this repository**: three checksummed models (hashes
enforced by `server/src/vision.rs`), MediaPipe 0.10.35's `libmediapipe.so`,
OpenCV shared objects, and their C++/JPEG/zlib/EGL/GLES runtime dependencies.
Keep only SONAME files, with no symlinks, and `$ORIGIN` RUNPATH on each shared
library. The deployed inventory and hashes are in
`docs/evidence/bundle-sizes.json`. There are no runtime downloads.

`build.sh` refuses to run when these are missing. Keep a durable copy: losing
them means no deploy is possible.

## Frontend generation stays on the host

`npm run client:prepare` runs outside the container, which sets
`NEXTRS_SKIP_BUNDLE=1` and reuses `server/public/dist`. Moving that step into
the image would ship stale static assets.

## Related

Production hosted-worker variables are listed in `server/.env.example`. Vercel
cannot return sensitive values after creation; keep `CRON_SECRET` and the
processor token in a secret manager.
